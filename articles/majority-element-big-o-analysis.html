Majority Element & Big-O Analysis

2026-06-07 • Algorithms • Notes

Problem

LeetCode 169: Majority Element (Easy) Given an array nums of size n, return the majority element.

The majority element is defined as the element that appears more than ⌊n / 2⌋ times. The majority element is guaranteed to exist.

Inputs

  • Input: Integer array nums of size n
  • Output: Integer majority element
  • Constraints: 1 ≤ n ≤ 5 × 10⁴, -10⁹ ≤ nums[i] ≤ 10⁹
  • Guarantees: A majority element always exists

Initial Thoughts

There is confusion about the meaning of “majority element”. It is not n/2 itself. Instead, n/2 represents the threshold: the majority element must appear more than ⌊n/2⌋ times.

A naive interpretation might incorrectly treat n/2 as the answer or a direct value, but it is only a frequency condition.

Key Insight

The majority element is defined by frequency dominance: it appears strictly more than half the array size.

This leads to two valid solution approaches:

  • Frequency counting using a hash map (simple but uses extra space)
  • Boyer-Moore Voting Algorithm (optimal: O(n) time, O(1) space)

Algorithm

Hash Map Approach:

 counts = {}

for num in nums:
counts[num] += 1

for each key in counts:
if counts[key] > n/2:
return key

Boyer-Moore Voting Algorithm:

 candidate = None count = 0

for num in nums:
if count == 0:
candidate = num

if num == candidate:
    count += 1
else:
    count -= 1

return candidate

Pseudocode

 # Hash Map Version Create empty dictionary counts For each number in nums: increment counts[number] For each (number, count) in counts: if count > floor(n / 2): return number # Boyer-Moore Voting Algorithm candidate = None count = 0 For each number in nums: if count == 0: candidate = number if number == candidate: count += 1 else: count -= 1 Return candidate

Complexity

Hash Map Solution:

Time: O(n)

Space: O(n)

Boyer-Moore Voting Algorithm:

Time: O(n)

Space: O(1)

Big-O Interpretation

Big-O describes how runtime or memory grows as input size increases.

  • O(1): Constant time, independent of input size
  • O(log n): Logarithmic growth, typically halving problem size each step (e.g., binary search)
  • O(n): Linear growth proportional to input size
  • O(n log n): Common in efficient sorting algorithms
  • O(n²): Quadratic growth, common in nested loops

Step-by-step reasoning examples

Single loop:

 for i in range(n): print(i)

Time: O(n)

Nested loops:

 for i in range(n): for j in range(n): print(i, j)

Time: O(n²)

Sequential loops:

 for i in range(n): print(i)

for j in range(n):
print(j)

Time: O(n + n) → O(n)

Simplification rules

  • Drop constants: O(5n) → O(n)
  • Keep dominant term: O(n² + n) → O(n²)
  • Nested loops multiply: O(n × n) → O(n²)
  • Sequential loops add: O(n + n) → O(n)

Pattern

This problem is a classic example of frequency dominance and cancellation-based algorithms.

Boyer-Moore works by pairing off different elements and eliminating non-majority candidates through cancellation.

Lessons Learned

  • n/2 is a threshold, not the answer itself
  • Majority element is defined by frequency, not value
  • Hash maps provide straightforward counting but use extra space
  • Boyer-Moore achieves optimal O(n) time and O(1) space
  • Big-O describes growth rate, not exact runtime
  • Nesting implies multiplication of complexity
